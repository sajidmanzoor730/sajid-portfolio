Support Automation Toolkit

A compact set of Python, Postman, SQL and Wireshark utilities designed to make routine support investigations more consistent: summarize SIP response patterns, define API checks, prepare service-desk reporting queries and narrow packet captures for review.

View source repository ↗ Explore the detailed VoIP case study
Project scope: This is a lightweight investigation toolkit, not an automated production diagnosis or remediation system. The files are examples that an engineer configures and validates in an authorised environment.
What it contains

Four practical support utilities

Each component addresses a different step in a support engineer's workflow.

Python · CSV

SIP log pattern summary

postman/sip_log_parser.py reads a local sip.log, counts lines matching SIP response codes and exports a CSV summary with basic suggested investigation actions. It is a text-pattern counter, not a full SIP parser.

Postman · API checks

Configurable endpoint health checks

postman/voip-api-health.json defines assertions for registration status, response time, packet-loss threshold and authentication response. Configure the base URL and adapt paths and response fields to the authorised test API before running.

SQL · Reporting

Support metrics query examples

sql/support_metrics.sql demonstrates issue-volume, CSAT/SLA and knowledge-base-linked ticket reporting. It assumes example table and column names; connect it to a real schema and validate KPI definitions before use.

Wireshark · Packet triage

Display-filter reference

wireshark/filters.txt collects starting filters for SIP responses, RTP/RTCP, STUN and HTTP errors. Filters help isolate traffic for inspection but do not prove root cause on their own.

Workflow

From symptom to evidence-led handoff

01 · COLLECT

Gather evidence

Use an authorised, sanitised SIP log, API endpoint or packet capture.

02 · SUMMARISE

Run checks

Generate a CSV pattern summary, run configured Postman assertions and apply packet filters.

03 · REPORT

Query metrics

Adapt SQL examples to the service-desk schema for operational reporting.

04 · VALIDATE

Engineer review

Confirm the full call flow and context before recording a cause or next action.

Run locally

Try the SIP log summary

# Place an authorised, sanitised text log named sip.log # in the repository's working directory, then run: python postman/sip_log_parser.py # Output: sip_rca_report.csv
Interpretation matters: a SIP 401 can be a normal digest-authentication challenge, and a text match for “RTP” with no “RTCP” does not establish one-way audio. Review the full SIP ladder, packet capture, endpoint and network context before concluding.
Evidence and limitations

What this repository does—and does not—prove

Included evidence

The repository contains scripts, a Postman test definition, SQL examples and filter references. It does not include a sample support database, production endpoint, credentials or exported passing Postman run.

Reported impact figures

Original notes mention 40% repeatable L1 patterns, 35% lower manual L1 effort, 28% KB/macro deflection and 95%+ CSAT. No dated ticket export, sample size or baseline calculation is supplied, so these are unverified project-note figures—not measured outcomes.
