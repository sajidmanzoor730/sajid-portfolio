Helpdesk KPI Dashboard

Data Dictionary

Field definitions for the structured helpdesk dataset used in the Helpdesk KPI Dashboard case study.

← Back to case study View dataset →
Purpose: This dictionary documents the fields used for data cleaning, validation, SQL analysis, KPI calculations, and dashboard reporting.

Dataset Fields

Core ticket, customer, SLA, resolution, quality, and operational fields.

Field Meaning Example / Values
Ticket_ID Unique support ticket identifier. HD-260301-01001
Created_At Timestamp when the ticket was created. 2026-03-01 09:15
First_Response_Minutes Minutes between ticket creation and the first response. 18
Resolved_At Timestamp when the ticket was resolved, when available. Timestamp / blank
Priority Support priority assigned to the ticket. P1, P2, P3, P4
Category / Subcategory Classification of the support issue. Network / VPN
Channel Channel through which the ticket entered the support workflow. Portal, Email, Chat, Phone
Customer_Segment Customer or account segment associated with the ticket. Enterprise, Mid-Market, SMB, Internal
Team / Agent Support team and assigned analyst responsible for the ticket. Service Desk L1 / Agent
Status Current state of the support ticket. Resolved, Closed, Pending, Open
SLA_Target_Hours Applicable resolution target based on ticket priority. 4, 8, 24, 72
Resolution_Hours Elapsed time between ticket creation and resolution. 3.5
SLA_Breach / Breach_Reason Indicates whether the SLA target was exceeded and the classified reason. Yes / workload
Reopen_Count Number of times the ticket was reopened after resolution. 0, 1, 2...
Escalated Indicates whether the ticket required escalation. Yes / No
CSAT Customer satisfaction score recorded for the ticket. 1–5
Is_Repeat Indicates whether the ticket represents repeat demand. Yes / No
Contact_Reason / Root_Cause Reason for contact and classified underlying cause. Access / Configuration
Region Operating region associated with the ticket. North America, EMEA, APAC

Data-Quality Rules

Key validation and cleaning rules applied before KPI reporting.

  • Duplicate Ticket_ID records are identified during data cleaning.
  • Missing Category values are handled consistently during preparation.
  • Missing Agent values are handled consistently during preparation.
  • Invalid or inconsistent date fields are checked before analysis.
  • Priority and SLA fields are validated before KPI calculations.
