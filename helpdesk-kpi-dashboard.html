Public IT Helpdesk Trends Dashboard

An end-to-end analytics project using a published government IT helpdesk summary dataset, with source ingestion, data validation, cleaning, trend analysis and interactive reporting.

Dataset disclosure: The live dashboard uses public, aggregated data from Montgomery County Government's MCG HelpIT Tickets dataset. These are published summary counts, not individual ticket records or private company data. SLA adherence, MTTR, agent productivity and average CSAT are not claimed because the source does not provide the required ticket-level fields.

Business question

How can public IT helpdesk summary data be cleaned and transformed into useful views of request types, contact channels, departments and changes across fiscal years?

Analytics workflow

1. Source data.
Load the published MCG HelpIT Tickets CSV from Montgomery County's open-data portal.
2. Validate and normalize.
Normalize source column names, parse fiscal years and numeric counts, remove unusable summary rows and check duplicate summary records.
3. Analyze.
Compare published request types, contact sources, department counts and survey-summary rows by fiscal year where available.
4. Communicate.
Use Streamlit filters, charts and tables to explore the published summaries, with limitations clearly documented.

Data cleaning & validation

Source controls

  • Required source columns are mapped by normalized names.
  • Fiscal year and count fields are converted to numeric values.
  • Rows with missing required fields are excluded.
  • Duplicate summary records are checked.

Interpretation controls

  • Report sections can overlap; their totals must not be added together.
  • Counts are published summary counts, not individual ticket rows.
  • Survey summaries are not individual CSAT ratings.
  • The dashboard shows an error rather than falling back to generated data if the source fails.

Interactive dashboard

The Streamlit dashboard fetches the official public CSV at runtime and caches it for one hour. It provides fiscal-year and report-section filters, charts for listed requests and contact channels, department summaries, survey-summary tables, and data-quality diagnostics.

What the data can tell us

  • Compare the published count of request types, such as Email Support and VPN, within the report's fiscal-year grouping.
  • Review contact-source counts such as calls, email and other listed channels.
  • Compare published contact counts by department.
  • Inspect survey summary rows without treating them as individual customer ratings.

These are descriptive observations from published summaries. They are not evidence of individual ticket resolution time, SLA compliance or agent performance.

Measure definitions & limitations

Published count: the count reported by the source for a fiscal year, report section and item.

Published percentage: the percentage provided in the source, retained where available.

Not calculated: SLA adherence, SLA breach rate, MTTR, agent productivity, repeat-ticket rate and average CSAT. The aggregated source does not contain the necessary individual-ticket fields.

SQL analysis

The repository retains an SQL learning example from the earlier synthetic ticket-level demo. It is explicitly marked as legacy and is not used to generate the current live dashboard metrics. The live dashboard calculations are based on the official aggregated public dataset.

Tools & skills

Python, Pandas, Streamlit, CSV ingestion, schema validation, data-quality checks, grouping and aggregation, trend comparison, interactive visualization, source documentation and responsible interpretation.
