KPI Reporting

KPI Operations Dashboard

An operational analytics dashboard built from the project dataset to monitor workload, completion, SLA achievement, QA performance and data quality.

Data note: This dashboard runs on the Operational KPI Dataset, a synthetic operational dataset of 7,500 records covering January–September 2026. The raw file (7,575 rows) was de-duplicated on Record_ID to produce the clean file used here. It contains no confidential employer or customer data, so the findings below illustrate the analysis approach rather than real business results.

Key findings

Calculated on the full dataset, independent of the filters below.

Finding 1

Every SLA miss is a P1 record

143 of the 145 SLA breaches (98.6%) are P1. P1 records meet SLA 67.6% of the time (299 of 442); P2–P4 records meet it 99.97% of the time.

Action: Focus SLA improvement on P1 handling. Adding capacity to lower priorities would not move the SLA figure.

Finding 2

Complexity decides whether P1 work breaches

Within P1, high-complexity records meet SLA only 10.9% of the time (7 of 64, averaging 109 minutes against a 60-minute target). Medium complexity meets it 51.4% of the time; low complexity meets it every time.

Action: Route high-complexity P1 records to experienced staff at intake and escalate them earlier.

Finding 3

Complexity drives resolution time everywhere

High-complexity records take 158 minutes on average against 33 minutes for low complexity, about 4.8 times longer, so record counts alone understate workload.

Action: Plan capacity using complexity mix, not just volume.

Finding 4

Teams and regions perform alike

SLA achievement ranges only from 97.7% to 98.6% across the five teams and from 97.6% to 98.6% across the five regions. No team or region is an outlier.

Action: Look at work type (priority and complexity) rather than team-level fixes.

Finding 5

Missing fields are the largest data-quality issue

97.3% of records pass validation. Of the 199 flagged, 108 have a missing field (54%), 58 a format issue and 33 are duplicate candidates.

Action: Add required-field checks at intake first; it removes the biggest share of issues.

Finding 6

QA scores cover only 87.5% of the work

937 records (12.5%) were not assessed. Of the 6,563 assessed, 62 (0.9%) went to review and none scored below 90, so the 97.9% average reflects assessed work only.

Action: Extend QA sampling to unassessed records before treating the average as the whole picture.

How the KPIs are defined

Definitions used by the dashboard, plus SQL that reproduces the headline figures.

Records
Rows in the current filtered view of the clean dataset.
Completion rate
Records with Status Completed or Closed ÷ records.
SLA achievement
Records with SLA_Status = Met ÷ records.
QA accuracy
Average QA_Score across assessed records only (QA_Result is not “Not Assessed”).
Items processed
Sum of Items_Processed.
Avg resolution
Average Resolution_Minutes across records.
Rework rate
Records with Rework_Flag = Yes ÷ records.
Data validity
Records with Data_Quality_Flag = Valid ÷ records.
SQL to reproduce these numbers (SQLite syntax)
SELECT COUNT(*) AS records,
  ROUND(100.0 * SUM(CASE WHEN Status IN ('Completed','Closed') THEN 1 ELSE 0 END) / COUNT(*), 1) AS completion_pct,
  ROUND(100.0 * SUM(CASE WHEN SLA_Status = 'Met' THEN 1 ELSE 0 END) / COUNT(*), 1) AS sla_pct,
  ROUND(AVG(QA_Score), 1) AS qa_accuracy,
  ROUND(AVG(Resolution_Minutes), 1) AS avg_resolution_min,
  ROUND(100.0 * SUM(CASE WHEN Rework_Flag = 'Yes' THEN 1 ELSE 0 END) / COUNT(*), 1) AS rework_pct,
  ROUND(100.0 * SUM(CASE WHEN Data_Quality_Flag = 'Valid' THEN 1 ELSE 0 END) / COUNT(*), 1) AS valid_pct
FROM operational_kpi;
SELECT Priority, COUNT(*) AS records,
  SUM(CASE WHEN SLA_Status = 'Breached' THEN 1 ELSE 0 END) AS breaches,
  ROUND(100.0 * SUM(CASE WHEN SLA_Status = 'Met' THEN 1 ELSE 0 END) / COUNT(*), 1) AS sla_pct
FROM operational_kpi
GROUP BY Priority
ORDER BY Priority;

SQL behind the findings

Findings 1 to 5 above come from these queries. The results below were produced by running these queries on the clean CSVs (SQLite). Reproduce them with python3 sql/run_sql.py.

kpi sla by priority

-- Finding: every SLA miss is a P1 record
SELECT Priority,
       COUNT(*)                                              AS records,
       SUM(SLA_Status = 'Breached')                          AS breaches,
       ROUND(100.0 * SUM(SLA_Status = 'Met') / COUNT(*), 2)  AS sla_met_pct
FROM kpi
GROUP BY Priority
ORDER BY Priority;

kpi p1 by complexity

-- Finding: complexity decides whether P1 work breaches
SELECT Complexity,
       COUNT(*)                                              AS p1_records,
       ROUND(100.0 * SUM(SLA_Status = 'Met') / COUNT(*), 1)  AS sla_met_pct,
       ROUND(AVG(Resolution_Minutes), 0)                     AS avg_minutes
FROM kpi
WHERE Priority = 'P1'
GROUP BY Complexity
ORDER BY sla_met_pct;
