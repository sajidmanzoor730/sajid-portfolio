Additional project · Email protocol diagnostics

SMTP/IMAP Troubleshooting Lab

A zero-dependency Python toolkit built around an L2 support workflow: determine whether an email connectivity or delivery failure is caused by DNS, TCP, TLS, authentication, transient server behavior or policy—and produce concrete next steps from the evidence.

View source on GitHub ↗Back to portfolio
01 / What it does

Diagnose the layer, not just the symptom.

SMTP

Outbound mail checks

Walk through TCP connection, server banner, EHLO, STARTTLS or implicit TLS, authentication and recipient-envelope checks.

IMAP

Mailbox connectivity

Probe IMAP over SSL or STARTTLS, inspect server responses and test password or XOAUTH2 authentication.

Diagnosis

Actionable failure mapping

Classify reply codes and socket/TLS errors into network, TLS, authentication, policy or transient categories with recommended next steps.

02 / Diagnostic workflow

From connection attempt to evidence-based next step.

01 · CONNECTDNS + TCP

Check name resolution, reachability, timeouts and refused connections.

02 · NEGOTIATESMTP / IMAP + TLS

Inspect protocol banners, capabilities, STARTTLS and certificate validation.

03 · AUTHENTICATELOGIN / XOAUTH2

Exercise authentication safely; mask credentials and bearer tokens in transcripts.

04 · CLASSIFYFailure category

Map server replies and transport errors to likely causes and practical checks.

05 · REPORTNext action

Produce readable or JSON output that can support repeatable troubleshooting.

03 / Safe reproduction

Reproduce failures without depending on a live mail provider.

Fault-injecting mock servers

Local SMTP and IMAP mocks reproduce unavailable STARTTLS, reset connections, authentication failures, relay denial, greylisting, banner errors and blackholed connections.

Security-conscious handling

Passwords and OAuth2 tokens are read from environment variables, authentication payloads are redacted, TLS verification is enabled by default and credentials are blocked on unencrypted connections unless explicitly overridden for local lab use.

Read-only verification

Probes do not send a message body. The SMTP envelope check stops after RCPT TO and issues RSET, avoiding message delivery during diagnostics.

04 / Authentication and test coverage

Modern authentication with repeatable local tests.

OAuth2 refresh exchange

Exchanges an already-issued refresh token for a short-lived access token. Interactive consent, initial authorization-code handling and persistent token rotation are outside the toolkit's scope.

SMTP / IMAP XOAUTH2

Supports bearer-token authentication flows for SMTP and IMAP, with token redaction in diagnostic transcripts.

Continuous integration

The latest checked CI run passed the test suite on Python 3.11, 3.12 and 3.13, with 54 tests per version. Provider-specific Gmail and Microsoft 365 smoke tests are opt-in and have not been claimed as completed.

05 / Run it locally

Quick start.

git clone https://github.com/sajidmanzoor730/smtp-imap-troubleshooting-lab.git
cd smtp-imap-troubleshooting-lab
python3 -m pip install -e .

# Explain a server reply
maillab explain 454 "4.7.0 TLS not available"

# Run the local mock and probe it
maillab mock smtp --mode starttls_unavailable --port 2525
maillab smtp 127.0.0.1 --port 2525 --mode starttls
Scope and safety: use the probes only against mail servers and accounts you own or are authorized to test. Provider smoke testing requires separately configured, user-authorized credentials. The project uses local mock servers for its automated protocol-failure tests.
