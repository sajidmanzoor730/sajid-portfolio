BI Validation & Monitoring

A practical validation framework for checking whether operational KPIs remain accurate and consistent from the source data through SQL analysis and dashboard reporting.

← Back to Helpdesk case study View Power BI model →
What this project demonstrates: Source-to-report reconciliation, data-quality checks, KPI validation and investigation workflows using the Helpdesk analytics project. The current implemented scope is the validation framework and KPI baseline; the separate Power BI model is documented as supporting BI work.

Source-to-report reconciliation

✓ Ticket volume

Compare unique Ticket_ID counts across the cleaned dataset, SQL analysis and BI reporting layer.

✓ SLA adherence

Reconcile the reported SLA percentage against the SQL KPI calculation before publishing the dashboard.

✓ Resolution & CSAT

Compare average resolution time and CSAT results against the curated dataset used for analysis.

✓ Repeat & escalation

Validate repeat-ticket and escalation metrics before using them in KPI reporting.

Data-quality gates

  • Ticket_ID should be unique after the cleaning step.
  • Created_At should be populated for valid ticket records.
  • Priority should contain a defined P1–P4 value.
  • Channel and Status should match the defined source values.
  • Resolved_At should not occur before Created_At.
  • SLA_Breach should contain a valid Yes/No value.
  • CSAT should remain between 1 and 5 when provided.
  • The curated dataset should contain valid records before KPI calculations run.

Refresh review

A refresh review checks the main data-quality and reconciliation indicators before relying on updated reporting.

  • Raw row count
  • Curated row count
  • Duplicate rows identified
  • Rejected or invalid records
  • Data-quality status
  • KPI reconciliation status

The Helpdesk analytics workflow exposes these checks so data preparation and reporting results can be reviewed together.

Investigation workflow

  1. Compare source and curated row counts.
  2. Review duplicate and invalid-record counts.
  3. Compare the affected KPI with the SQL baseline.
  4. Break the metric down by date, priority, team and category.
  5. Inspect the underlying records contributing to the difference.
  6. Document the cause before changing the reporting logic.

Validation principles

✓ Reconcile before reporting

Validate important metrics against the underlying analytical dataset instead of relying only on dashboard output.

✓ Investigate differences

Trace unexpected KPI changes back through filters, calculations and source records.

✓ Document assumptions

Keep KPI definitions, validation rules and data-quality decisions clear and reproducible.

✓ Validate before publishing

Use quality checks as part of the reporting workflow rather than treating validation as a final step.

Project scope: This portfolio project demonstrates BI validation and monitoring practices using the Helpdesk analytics workflow. It does not claim a live enterprise Power BI gateway, production data warehouse, scheduled enterprise refresh or automated alerting infrastructure.

Worked example: the checks, running

The framework above is demonstrated here on the Operational KPI dataset, because that is the data included in this portfolio; it is not run on the helpdesk tickets. The script computes the same KPIs three independent ways, compares them with the figure printed on the dashboard page, then runs data-quality gates in the style described above. It exits with code 1 if anything fails, so it can block a report refresh. Run it with python3 scripts/reconcile_kpis.py.

#!/usr/bin/env python3
"""Source-to-report reconciliation and data-quality gates (pandas + stdlib).

    python3 scripts/reconcile_kpis.py

1. Computes the same KPIs three independent ways (pandas, SQL, plain csv module) and
   requires all three to agree.
2. Compares the result with the figure published on kpi-operations-dashboard.html.
3. Runs data-quality gates. Exit code 1 if any reconciliation or gate fails, so it can
   block a report refresh.
"""
import csv
import re
import sqlite3
import sys
from pathlib import Path

import pandas as pd

ROOT = Path(__file__).resolve().parent.parent
DATA = ROOT / "data/Operational_KPI_Dataset_Clean.csv"
PAGE = ROOT / "kpi-operations-dashboard.html"
failures = []


def check(label, ok, detail=""):
    print(f"  [{'PASS' if ok else 'FAIL'}] {label}" + (f"  ({detail})" if detail else ""))
    if not ok:
        failures.append(label)


df = pd.read_csv(DATA, dtype=str, keep_default_na=False)
for c in ("Resolution_Minutes", "SLA_Target_Minutes", "QA_Score"):
    df[c] = pd.to_numeric(df[c], errors="coerce")

# ---- 1. same KPIs, three ways ------------------------------------------------
print("1) Reconciliation: three independent calculations")
pandas_val = {"rows": len(df), "breaches": int((df.SLA_Status == "Breached").sum()),
              "p1_breaches": int(((df.SLA_Status == "Breached") & (df.Priority == "P1")).sum())}

con = sqlite3.connect(":memory:")
df.to_sql("kpi", con, index=False)
sql_val = dict(zip(("rows", "breaches", "p1_breaches"), con.execute(
    "SELECT COUNT(*), SUM(SLA_Status='Breached'), SUM(SLA_Status='Breached' AND Priority='P1') FROM kpi").fetchone()))

with open(DATA, newline="", encoding="utf-8-sig") as f:
    rows = list(csv.DictReader(f))
py_val = {"rows": len(rows),
          "breaches": sum(r["SLA_Status"] == "Breached" for r in rows),
          "p1_breaches": sum(r["SLA_Status"] == "Breached" and r["Priority"] == "P1" for r in rows)}

for k in pandas_val:
    check(f"{k}: pandas = SQL = csv module", pandas_val[k] == sql_val[k] == py_val[k],
          f"{pandas_val[k]} / {sql_val[k]} / {py_val[k]}")

# ---- 2. compare with the published page --------------------------------------
print("\n2) Dashboard page vs data")
html = PAGE.read_text(encoding="utf-8")
m = re.search(r"(\d+) of the (\d+) SLA breaches", html)
check("page says P1 breaches", m and int(m.group(1)) == pandas_val["p1_breaches"],
      f"page {m.group(1) if m else '?'} vs data {pandas_val['p1_breaches']}")
check("page says total breaches", m and int(m.group(2)) == pandas_val["breaches"],
      f"page {m.group(2) if m else '?'} vs data {pandas_val['breaches']}")

# ---- 3. data-quality gates ---------------------------------------------------
print("\n3) Data-quality gates")
check("Record_ID is unique", df.Record_ID.is_unique)
check("Created_Date is populated", (df.Created_Date != "").all())
check("Priority is P1-P4", df.Priority.isin(["P1", "P2", "P3", "P4"]).all())
check("SLA_Status is Met or Breached", df.SLA_Status.isin(["Met", "Breached"]).all())

done = df[df.Completed_Date != ""]
created, completed = pd.to_datetime(done.Created_Date), pd.to_datetime(done.Completed_Date)
bad_order = int((completed < created).sum())
check("Completed_Date is not before Created_Date", bad_order == 0, f"{bad_order} violations")

met_calc = done.Resolution_Minutes <= done.SLA_Target_Minutes
mismatch = int((met_calc != (done.SLA_Status == "Met")).sum())
check("SLA_Status agrees with resolution time vs target", mismatch == 0, f"{mismatch} mismatches")

qa = df.QA_Score.dropna()
check("QA_Score is between 0 and 100", qa.between(0, 100).all(), f"{len(qa):,} scored rows")

print(f"\n{'ALL CHECKS PASSED' if not failures else str(len(failures)) + ' CHECK(S) FAILED'}")
sys.exit(1 if failures else 0)
